### CI hardening (25 Oct, from the first GitHub Actions runs on `feat-new-components`)
- `pnpm/action-setup` takes its version from `packageManager` only; the docs `typecheck` script runs `next typegen` first (`PageProps`/`LayoutProps` live in generated `.next/types`); the install-check job installs every `registry:ui` item (the consumer `App.tsx` uses all of them) and reaches the static server over 127.0.0.1.
- `pnpm build` now generates the registry through the root task `//#build:registry` (see Foundation above).
- E2e specs import `test`/`expect` from `tests/e2e/fixtures.ts`, whose `page.goto` waits for `<html data-hydrated="true">` (set by `HydrationMarker`, rendered as the last child of every page because under `cacheComponents` the page segment sits in `<Activity>` boundaries that hydrate in a later idle pass than the root layout). Playwright's `load` fires before React attaches handlers; on the slower runner a fill, focus or key press right after navigation hit un-hydrated markup and was lost (focus-graph search stayed unfiltered; adaptive-rail, flow-stack-gallery and the focus-graph deletion example were flaky for the same reason). Measured with 8× CPU throttling against the dev server: `load` fired after 4–8 s while `/components/focus-graph` finished hydrating 12–20 s later; the gated search, arrow-key, slider and delete interactions all succeeded. Unit-test timing: `ParticleMorph` completion is awaited separately from readiness.
- Still only verified locally in CI mode (`CI=true pnpm test:e2e` against a build made with the 3100 origin); the GitHub run itself is the proof.

### Docs CSS fix (24 Oct, during OrbitalMenu)
- Tailwind only scanned `apps/docs`, so utilities used solely inside `packages/ui` were missing from the docs CSS (component sizes, variable-backed colours, data-state styles). Fixed with `@source "../../../../packages/ui/src"` in `globals.css`; visual baselines regenerated. Consumers were never affected. See DECISIONS 011.
- Galleries must never scroll the page on mount: an early FlowStackGallery build called `scrollIntoView` for the active thumbnail on mount, which dragged the docs page to the last example. The scroll now runs only on later index changes (and survives StrictMode's double effects).
- The playground stage wrapper now has a definite width (`w-full` flex), so grid components get real column counts in previews; before, percentage widths resolved against a shrink-to-fit box and grids collapsed to one column.
- Smooth scrolling was removed from the docs: it made Playwright's scroll-into-view retry loop never settle, and reduced-motion users get instant jumps anyway.
